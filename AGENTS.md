# Scrollect

## What it is

Scrollect is an AI-powered personal learning feed. It transforms saved content (books, articles, videos, PDFs) into a scrollable feed of bite-sized learning cards — like social media, but built from your own knowledge.

## Target user

Software engineers and active learners who consume a lot of content but struggle to retain and connect what they learn.

## Key principles

- **Personal, not social** — no followers, no comments, no public profiles
- **Scroll-native UX** — don't fight the scroll, redirect it
- **AI-first** — the feed is generated by a dedicated AI agent
- **Low friction input** — adding content should take seconds

## Tech stack

- **Monorepo**: Turborepo + Bun
- **Web app**: TanStack Start (`apps/web`)
- **Docs**: Starlight (`apps/docs`)
- **Presentation**: Slidev (`apps/presentation`)
- **Backend**: Convex (`packages/backend`)
- **Auth**: Better-Auth

## Does

- Use AskUserQuestion to proactively ask questions. Be proactive, curious, pay attention to the details.
- Write E2E tests when working on a new feature / bug fix
- 100% test coverage is less important than test stability. If a test is hard to write and hard to maintain, skip it
- Must use shadcn on the Frontend
- **Always deploy after changing Convex schemas or functions**: run `cd packages/backend && npx convex dev --once` to push changes to the dev deployment
- **Split large components**: Extract reusable logic into custom hooks (`hooks/`) and shared UI into dedicated component files. Keep page components thin — they compose hooks and components, not raw logic
- Don't declare functions with more than 3 parameters. Merge the parametrs into object instead to avoid a risk of passing parameters in incorrect order
- Prefer using TDD approach with /tdd skill

## Convex backend

- **External I/O before state transitions**: Complete all external operations (Qdrant, APIs) BEFORE updating document status. External calls are not transactional with Convex mutations
- **No unbounded `.collect()` on user-facing queries**: Always paginate or `.take(limit)`. Use unbounded `.collect()` only in internal mutations where completeness is required (cascade delete)
- **Batch over loops**: Use batch mutations with `Promise.all` instead of sequential `ctx.runMutation` loops. N sequential calls add ~N\*10ms overhead

## Frontend

- **`<Link>` not `<a>` for internal navigation**: Plain anchors destroy the React tree, WebSocket subscriptions, and query cache - even inside toasts
- **Filter state in URL search params**: Use `validateSearch` + `Route.useNavigate()`, not `useState`. Survives navigation, shareable, integrates with browser history
- **Convex-native data fetching**: Use `useQuery`/`usePaginatedQuery` for real-time data, not `useSuspenseQuery` with convexQuery adapter. Removes unnecessary loader blocking and mixed cache layers

## DON'T

- Don't add code separators in the code. No "// --- Section ---", instead try to better structure the code and files so such comments won't be necessary.
- Avoid coincidental cohesion (for example in helpers / utils files)
- **Never modify `apps/web/src/routeTree.gen.ts` directly** - it is auto-generated by TanStack Router's Vite plugin when the dev server runs. Add new route files to `apps/web/src/routes/` and the route tree will regenerate automatically.
- **Running E2E tests requires a dev server**: start the dev server with `bun turbo dev --filter "@scrollect/web"`. Prefer running only added and/or modified tests, as all tests will be run in CI
- **No `waitForTimeout` in E2E tests**: Use event-driven waits. Convex data arrives via WebSocket, not HTTP - `page.waitForResponse()` cannot detect data updates
